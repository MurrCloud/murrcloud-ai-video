# Server assessment template

Complete this template privately before proposing a deployment. This source copy
contains no host inventory, deployment authorization or production measurements.
Do not commit completed operational records, credentials or customer evidence.

| Assessment item | Private operator record |
| --- | --- |
| Assessment timestamp and reviewer | To complete |
| Authorized host identity and strict SSH host-key verification | To complete |
| OS, kernel, Docker and Compose compatibility | To complete |
| CPU, RAM, swap and representative peak load | To complete |
| Root/storage free bytes, inodes, quotas and I/O | To complete |
| Protected workloads and health probes | To complete |
| Existing listeners, networks, routes and certificates | To complete |
| Dedicated Studio network and storage design | To complete |
| Independent credentials and secret custody | To complete |
| Current recovery points and isolated restore results | To complete |
| Studio image/source identities and isolated acceptance | To complete |
| Admission thresholds and fresh read-only host signal | To complete |
| Explicit change scope, maintenance plan and rollback | To complete |

Use only read-only assessment commands with scoped authorization. Preserve
unrelated services, databases, mounts, credentials and routes. Low sampled load
and container ceilings do not establish sustained capacity. Missing, stale or
unhealthy host admission must reject new media work. Synthetic CI signals belong
only in disposable test environments.

Keep paid video, director, narration, rendering and S3 disabled, provider runtime
keys blank and workers opt-in until their individual configuration, acceptance
and authorization gates are satisfied. A completed assessment alone grants no
permission to change infrastructure or submit a provider request.
